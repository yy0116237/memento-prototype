# Memento「定格」· 演出记录

> 一款 AI 辅助的演出记忆记录工具：降低散场后的表达成本，把容易消散的现场细节整理成可回看、可编辑、可收藏的手绘纪念海报。

Memento 面向看完演出后“想记录，但不知道怎么写或不想排版”的用户。产品通过 **Snap** 轻量提问与 **Murmur** 自由表达承接不同记录习惯，再由 AI 辅助完成演出信息填充、文字整理、情绪识别、金句和标签生成。

> 当前产品阶段：**3.0 中文 Beta**。代码保留中 / 英 / 韩三语字典，但当前界面语言固定为中文；这不等同于三语版本已经正式上线。

---

## 产品价值

演出结束后的高情绪窗口很短。照片能保存画面，却很难保留排队经历、邻座互动、意外瞬间和散场后的真实感受。传统日记和内容平台又要求用户组织长文、排版或主动分享。

Memento 希望解决三个具体摩擦：

| 用户摩擦 | 产品回应 |
| --- | --- |
| 不知道从哪里开始写 | Snap 用短问题降低启动成本 |
| 有很多碎片感受，但不想组织语言 | Murmur 接收自由输入，AI 提供可编辑草稿 |
| 写完还要排版才能保存或分享 | 自动生成手绘纪念海报并导出 PNG |

产品的核心价值不是“替用户创作”，而是帮助用户更容易地保存自己的真实记忆。AI 输出始终可以修改；AI 不可用时，用户仍应能够手动填写和保存记录。

## 核心体验

```text
注册 / 登录
    ↓
搜索演出 → AI 填充演出信息 → 用户确认或手动修正
    ↓
选择记录方式
    ├─ Snap：通过轻量问题完成记录
    └─ Murmur：自由输入，选择保留原文或让 AI 整理
    ↓
AI 生成情绪、金句与标签
    ↓
用户预览和编辑 → 保存记录 → 导出海报
    ↓
在个人时间线中回看、补充或删除
```

### 主要功能

- **用户名认证**：使用用户名与密码注册、登录；注册时校验确认密码，支持密码显示/隐藏和提交 loading 状态。
- **演出信息填充**：AI 根据关键词返回演出名称、日期、场馆与城市；结果可修改，失败时回退到手动填写。
- **Snap / Murmur 双模式**：兼顾低输入成本与自由表达。
- **AI 辅助整理**：覆盖搜索填充、Murmur 润色与情绪识别、海报金句与标签三个触点。
- **手绘纪念海报**：用户可检查和修改内容，并导出为高清 PNG。
- **个人时间线**：记录按演出日期排列，可打开、补充和删除。
- **明确删除确认**：使用手绘风格确认弹窗，并提示删除后无法恢复。

## 项目边界与界限

这一部分用于说明 3.0 当前解决什么问题、明确不做什么，以及 AI、数据和技术能力的责任边界。

### 1. 当前产品范围

- 服务于**个人演出记忆记录**，核心闭环是“开始记录 → AI 辅助 → 用户确认 → 保存 → 回看 / 导出”。
- 当前以移动端场景和中文用户体验为优先，桌面端提供居中适配。
- 记录属于登录用户的私人数据，通过云端数据库持久化。
- 3.0 重点验证首条记录完成率、AI 输出接受度、海报导出率和用户回访意愿。

### 2. 明确不做

- **不做票务平台**：不提供购票、转票、验票、座位或票价服务。
- **不做演出资讯数据库**：AI 填充是记录辅助功能，不承诺覆盖所有艺人、城市和场次。
- **不做公开社交社区**：当前没有关注、评论、公开动态、私信或同场用户匹配。
- **不做专业图片编辑器**：只提供约束范围内的海报内容编辑和导出，不提供复杂模板、图层或修图能力。
- **不做权威情绪判断**：情绪标签仅用于记录分类和视觉表达，不构成心理分析或人格结论。
- **不做全自动内容发布**：导出后由用户自行决定是否以及在哪里分享。
- **暂不提供共感计数、歌单展示和独立记录库页面**；是否加入由真实用户验证结果决定。

### 3. AI 能力边界

- AI 通过 Supabase Edge Function `ai-chat` 调用 Meoo 云 AI `qwen3.6-plus`，前端不保存模型密钥。
- 演出搜索结果可能不完整或不准确，所有字段必须允许用户确认和修改。
- 模型不能确认演出信息时，应返回空值或缺失字段，而不是编造确定答案。
- 润色、金句、情绪和标签都是建议；最终保存内容由用户决定。
- AI 请求失败、超时或返回格式异常时，产品应保留用户输入，并提供手动填写、保存原文或重试路径。
- 不以 AI 输出替代事实核验，也不将生成内容表述为官方演出资料。

### 4. 数据与隐私边界

- 用户数据存储于 Meoo Cloud（Supabase）的 `profiles` 和 `records` 表。
- Row Level Security（RLS）用于限制用户只访问和修改自己的资料与记录。
- `basic_auth` 在实现层将用户名映射为 `{username}@meoo.local` 虚拟邮箱；虚拟邮箱只是认证技术细节，不是用户的真实邮箱服务。
- 日志不应记录密码、完整访问令牌、模型密钥或用户的完整私密正文。
- 用户删除记录前会看到“删除后无法恢复”的确认提示；当前版本不承诺回收站或数据恢复。
- 如需迁移旧版 `localStorage` 数据，必须先获得用户明确确认，不静默上传本地记录。
- 正式公开测试前仍需补充隐私说明、数据保留周期以及账号找回 / 密码重置方案。

### 5. 国际化边界

- `src/lib/i18n.ts` 维护 `zh`、`en`、`ko` 三语字典。
- 当前 `lang` 固定为 `zh`，因此对外口径为“中文 Beta”。
- 英文和韩文版本需要分别完成母语文案审校、AI Prompt 评测、字体与换行测试、移动端测试和海报导出验收后才能开放。

### 6. 运营与验证边界

- 当前阶段以小规模真实用户验证为主，不将原型反馈直接等同于市场需求成立。
- 建议北极星指标为“每周完成并保存的有效演出记录数”。
- 重点观察注册成功率、首条记录完成率、AI 成功率与接受率、海报导出率、AI 失败后的任务完成率和 7 日回访。
- 公开承诺以已经实现并完成验收的能力为准；规划中的功能不计入当前产品能力。

## 技术架构

| 层级 | 方案 | 说明 |
| --- | --- | --- |
| Web 应用 | React 19 + Vite | 从单文件原型升级为组件化工程 |
| 路由 | TanStack Router | 管理认证与应用页面路由 |
| 样式 | Tailwind CSS v4 | 设计 token 与响应式样式 |
| UI 组件 | shadcn/ui | 表单、Toast、AlertDialog 等基础交互 |
| 云服务 | Meoo Cloud（Supabase） | Auth、Postgres、RLS、Edge Functions |
| AI 代理 | `ai-chat` Edge Function | 隐藏密钥，统一三个 AI 触点 |
| AI 模型 | Meoo 云 AI `qwen3.6-plus` | 搜索填充、文字整理、金句与标签 |
| 国际化 | `src/lib/i18n.ts` | 三语字典；当前仅启用中文 |
| 海报导出 | html2canvas 1.4.1 | 导出前对颜色、字体和 SVG 滤镜做兼容处理 |

### AI 三个触点

1. **搜索填充**：根据艺人 / 组合、城市和年份等关键词返回结构化演出信息。
2. **Murmur 整理**：返回润色文本与 `excited / touched / funny / calm / default` 情绪标签。
3. **海报内容**：从用户记录中提炼一句金句和 3–5 个相关标签。

三个触点使用统一的 Edge Function、响应结构、超时处理和错误分类。前端在请求期间禁用重复提交；服务端应设置用户级速率限制、输入长度限制和成本告警。

## 数据模型与权限

### `profiles`

保存用户资料，包括用户 ID、用户名、首选语言和创建 / 更新时间。用户名应有唯一性约束，并明确大小写和字符规范。

### `records`

保存用户的演出记录，包括：

- 演出名称、日期、场馆、城市；
- Snap / Murmur 模式；
- 用户原始输入与最终保存文本；
- 情绪、标签和海报元数据；
- 用户 ID、创建时间和更新时间。

### RLS 原则

- 用户只能读取和更新自己的 `profile`。
- 用户只能创建、读取、更新和删除自己的 `records`。
- Edge Function 应使用登录用户的 JWT 确认身份，不能把前端传入的 `user_id` 当作授权依据。

## 视觉与交互

- 页面背景为极浅灰 `oklch(0.975 0.003 90)`。
- 触发按钮区、演出表单、精选卡片和时间线卡片统一使用奶白 `--cream: #fdfbf6`。
- 搜索框、AI 填充按钮和退出按钮使用 `CrayonRect` 手绘蜡笔边框。
- 点击板块后短暂悬浮，并随机切换低饱和边框颜色；动画结束后恢复灰色。
- 搜索、生成和保存拆分为独立按钮，各自承担清晰的动作和状态反馈。
- 模式名统一为 **Snap** 和 **Murmur**。
- 演出名称按语义自然换行，避免逐字断裂。
- 删除确认使用手绘风格 `AlertDialog`，不再使用原生 `window.confirm`。
- 对开启“减少动态效果”的用户，应取消悬浮和重绘动画，保留必要状态反馈。

## 海报导出兼容处理

html2canvas 1.4.1 无法直接解析部分 `oklch()` 颜色和字体 CSS 变量，可能产生 `CSSParsedDeclaration2` 错误。导出时在 `onclone` 中：

1. 遍历海报节点及子元素；
2. 使用 `getComputedStyle` 获取实际样式；
3. 将包含 `oklch` 的 `color`、`background-color` 和 `border-color` 覆盖为可解析的实际 hex / rgb 值；
4. 将 `var(--font-*)` 替换为实际字体栈；
5. 移除导出节点中的 SVG 噪点滤镜引用。

导出成功和失败均通过 Toast 给出反馈，并保留中文、英文和韩文词条。

## 本地开发

> 以下命令适用于 3.0 React 工程。请勿把 `.env`、模型密钥或云服务密钥提交到仓库。

```bash
npm install
npm run dev
```

生产构建：

```bash
npm run build
npm run preview
```

云端运行还需要配置 Meoo Cloud / Supabase 项目、数据库迁移、RLS 策略和 `ai-chat` Edge Function 所需的服务端环境变量。具体变量名应记录在 `.env.example`，但示例文件不得包含真实密钥。
